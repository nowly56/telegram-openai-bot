# Telegram-бот с OpenAI API

Бот работает через Telegram long polling и OpenAI Responses API. По умолчанию используется `gpt-5.6-sol`. Сторонние npm-пакеты не нужны. Требуется Node.js 24+: используется встроенный SQLite (`node:sqlite`, в Node 24 может выводиться ExperimentalWarning).

## Запуск

1. В Telegram откройте `@BotFather`, выполните `/newbot`, задайте имя и username, который заканчивается на `bot`, и скопируйте выданный токен.
2. Создайте OpenAI API key в [панели API keys](https://platform.openai.com/api-keys). Не отправляйте ключ в чат и не публикуйте его.
3. Скопируйте `.env.example` в `.env` и заполните `TELEGRAM_BOT_TOKEN` и `OPENAI_API_KEY`.
4. Запустите `npm start` и оставьте это окно работающим. В Windows можно просто открыть файл `start-bot.cmd` двойным щелчком.
5. Откройте бота по ссылке `https://t.me/<username>` и нажмите Start.

## Добавление в группу

Добавьте бота в нужную группу как участника. В группе Роберт отвечает, когда его называют по имени «Роберт» или используют `/ask`. Сообщения, являющиеся ответами на другие сообщения, он игнорирует.

Если бот должен видеть каждое сообщение в группе, в `@BotFather` выполните `/setprivacy`, выберите бота и установите `Disable`. Это менее приватный режим: после этого бот будет получать все сообщения группы.

## Поведение

- `/start` и `/help` показывают подсказку.
- `/reset` очищает контекст текущего чата.
- Полная история сообщений сохраняется в SQLite (`data/bot.sqlite`) и восстанавливается после перезапуска.
- Чтобы получать обычные сообщения группы для контекста, отключите Privacy Mode через `@BotFather` командой `/setprivacy` → `Disable`.
- Запросы к OpenAI отправляются с `store: false`.
- Длинные ответы автоматически разбиваются на сообщения Telegram.

## Отчёты и игровой рейтинг

Администратор группы задаёт расписание командами:

```text
/reports daily 21:00 Europe/Moscow
/reports weekly 10:00 Europe/Moscow 1
/reports status
/reports rating
/reports off daily
/reports off weekly
/reports reset
```

Дни недели: 0 — воскресенье, 1 — понедельник, …, 6 — суббота. Часовой пояс можно заменить на другой IANA timezone. Отсчёт первого периода начинается при настройке. После простоя отправляется один просроченный отчёт; следующий охватывает накопившийся период. Дневные отчёты не меняют рейтинг; недельные обновляют его после успешной отправки. Стартовый рейтинг каждого известного участника — 5, шкала 0–10. Формула: активность +1 за 5 и более сообщений, юмор +0/1, поведение −1/0/+1. При отсутствии сообщений рейтинг не меняется. `/reports reset` сбрасывает оценки и начало периода, историю не удаляет.

Количество сообщений считается по всему периоду; субъективные оценки и доброжелательные прозвища — по последним 20 сообщениям каждого активного участника (до 600 символов каждое). Это игровой обзор общения, не оценка личности. Бот знает авторов полученных сообщений и новых вступивших участников, но не может восстановить полный список молчавших участников или переписку до подключения. Старый архив без дат и ID сохраняется для диалога, но не используется в статистике. Учитываются тексты и подписи к медиа; редактирования, удаления, реакции и содержание голосовых не анализируются.

История, память, расписание, рейтинг и прогресс доставки хранятся в одной SQLite-базе. На Railway нужен постоянный Volume `/data`, `CONTEXT_FILE=/data/chat-context.json` и ровно одна реплика бота. Бот должен непрерывно работать; таймер проверяется каждые 15 секунд. Повтор после явного отказа Telegram — через 5 минут. Уже подтверждённые части отчёта повторно не отправляются. При неопределённом результате сети или перезапуске во время отправки бот приостанавливает спорную часть и пытается один раз уведомить чат. Посмотреть состояние: `/reports status`. Если спорная часть получена — `/reports delivered weekly` (или `daily`); если нет — `/reports retry weekly`. Последняя команда разрешает повтор, который может создать дубль, если Telegram всё же доставил предыдущую попытку. Абсолютной гарантии exactly-once нет. Рейтинг применяется только после завершения всех частей, вместе с переносом следующей даты в одной атомарной записи.

В обычный запрос API передаётся краткая память (до 6000 символов) и последние 200 записей, до 6000 символов каждая и до 40000 символов суммарно. Раз в минуту старые сообщения постепенно сворачиваются в память: до 100 записей за проход, до 1000 символов каждой; последние 40 остаются свежим контекстом. Полный архив не удаляется. Сводка может терять детали; это не поиск по всему архиву. Создание сводок расходует API-кредиты. При ошибке старая память сохраняется, повтор через 5 минут. `/reset` очищает историю и сводку; в группе доступен только администраторам. Сообщения-ответы сохраняются, но не вызывают ответ бота.

## Расписание обычной фразой

Напишите отдельное сообщение: `Роберт, присылай отчёт каждый понедельник в 10:00 по Москве` или `Роберт, присылай отчёт каждый день в 21:00 Asia/Yekaterinburg`. Можно запросить дневной и недельный отчёты одновременно на одно время. Без времени предлагается 10:00, без часового пояса — Europe/Moscow, для недельного отчёта без дня — понедельник. Бот явно показывает все значения перед сохранением. Свободный текст распознаётся ограниченным набором правил, не моделью; сложные интервалы требуют явных команд.

Бот выдаст `/reports confirm <код>`. Подтвердить может только автор предложения, который по-прежнему является администратором, в течение 10 минут. Повторное подтверждение не применяется. `/reports cancel` отменяет предложение. Фраза о стартовом рейтинге 5 добавляет сброс рейтинга к подтверждаемым действиям. Неподтверждённая просьба не создаёт таймер, не меняет оценки и не включает отчёты.

## Обновление с JSON на SQLite

При первом запуске архив из `CONTEXT_FILE` и файл `CONTEXT_FILE.reports.json` импортируются одной транзакцией. Оригиналы остаются нетронутыми. Импорт помечается выполненным и не повторяется после `/reset` или перезапуска. База по умолчанию находится рядом с `CONTEXT_FILE` под именем `bot.sqlite`; переменная `DATABASE_FILE` позволяет изменить путь. Не указывайте для базы путь старого JSON-файла.

Перед обновлением остановите старую копию, сохраните резервную копию каталога данных, затем запустите новую версию с тем же постоянным диском. Не запускайте старую и новую версии одновременно. Для отката остановите новую версию и используйте сохранённые JSON-файлы со старой версией; сообщения после миграции в них не появятся. Для резервной копии SQLite остановите бот и копируйте весь каталог данных, включая возможные файлы `-wal` и `-shm`. Секреты и базу нельзя коммитить.

Для обращений «Роберт,» отключите Privacy Mode в BotFather и повторно добавьте бота в группу. Если обращение отправлено как ответ на другое сообщение, бот намеренно молчит. Для проверки используйте новое самостоятельное сообщение `/ask@username_бота привет`.

Проверка кода: `npm run check` и `npm test`.
